# あたまんなか

頭に浮かんだことを、ひとりチャットのように書き流す iOS アプリです。
書いたメモのうち「やること」になったものは、スワイプひとつでタスクにできます。
未完了のタスクは、ホーム画面のウィジェットで確認できます。

Web 版の試作(HTML/JavaScript)で使い心地を確かめてから、SwiftUI で作り直しました。

## 機能

| 画面 | できること |
|---|---|
| チャット | 画面下の入力欄から書く。本文の横に追加時刻を小さく表示する。5分以上あいたメモの間には薄い線、日付が変わると見出しを出す。開いたときは新しい500件だけを読み込み、いちばん上までスクロールすると前の500件を読み足す |
| チャット → タスク | メモを右へスワイプすると、タスクになる。元のメモの左にオレンジ(#FC9325、不透明度 80%)の縦のバーが付く。タスクを完了すると、バーが同じ明るさの灰色になり、本文が薄くなる。同じく右へスワイプして出るボタンで、タスクを解除できる |
| メモの削除 | メモを左へスワイプして削除し、直後は「元に戻す」を出す。そのメモから作ったタスクは残す |
| タスク | 丸をタップして完了。完了したタスクは下に薄く残し、もう一度タップすると戻せる。長押しして上下に並べ替える。題名をタップして編集。左へスワイプして削除する。完了したタスクはまとめて削除できる。削除の直後は「元に戻す」を出す |
| ウィジェット | 未完了のタスクを一覧の並び順に、高さに入るだけ上から表示する(小・中サイズは5件、大サイズは13件ほど)。入る件数ぶんの枠を上下の中央に置き、タスクはその枠の上から並べる(件数が少なくても、上の余白は変わらない)。タスクがないときは「タスクはありません」を中央に出す。そのうち1行に色を敷き、15分ごとに入れ替える。タップするとタスク一覧を開く |

## 動かし方

必要なもの: Xcode 27 以降(Xcode 27.0 で確認)、iOS 18 以降、[XcodeGen](https://github.com/yonaskolb/XcodeGen)

```sh
brew install xcodegen
xcodegen generate
open Atamannaka.xcodeproj
```

実機で動かすときは、自分のチーム ID を `Configs/Local.xcconfig` に書きます(このファイルは git 管理外です)。

```
DEVELOPMENT_TEAM = ABCDE12345
```

チーム ID は Xcode の Settings → Accounts で確認できます。
Bundle ID はほかの人と重複できないため、自分で動かすときは `project.yml` の `com.yukarii` を書き換えてください。
App Group の ID(`group.com.yukarii.atamannaka`)も、`project.yml`、`SharedStore.swift`、2つの `.entitlements` で合わせて書き換えます。

テスト:

```sh
xcodebuild test -project Atamannaka.xcodeproj -scheme Atamannaka -destination 'platform=iOS Simulator,name=iPhone 18 Pro'
```

## 設計の判断

### メモとタスクを別のデータにした

タスクは、メモを指す参照を持つ別のデータ(`TaskItem`)です。メモに「タスクかどうか」の印を足す方式にはしていません。

- メモは「そのとき書いた記録」なので、タスクの題名を直しても元のメモは変えたくない
- タスクを削除してもメモは残し、ハイライトだけ外したい

- 逆にメモを削除しても、そこから作ったタスクは残したい。タスクはもう独り立ちした「やること」なので

この3つを素直に表せるのが、データを分ける方式でした。
削除時は SwiftData の `deleteRule: .nullify` で相手側の参照が外れ、ハイライトも自動で消えます。
メモの削除を元に戻したときは、タスクが残っていればつなぎ直し、ハイライトも戻します。

### スワイプの向きをタブの並びにそろえた

タブは左から「チャット」「タスク」の順に並べています。
メモを右へスワイプすると、タスク(右側のタブ)へ送る、という対応にしました。
左スワイプは、チャットでもタスク一覧でも、iOS の標準的な操作にそろえて削除にしています。
誤操作で消えないよう、全部スワイプしただけでは消さず、ボタンを押して削除します。削除の直後には「元に戻す」も出します。
「元に戻す」の表示は、動きで気が散らないよう、短いフェードで出し入れするだけにしています。

### 完了はチェックの1タップだけにした

完了は、行の左の丸を押すだけです。完了したタスクは消さず、下に薄く残します。
「何を終えたか」が見えること、押し間違えてももう一度押せば戻せることを優先しました。

### タスクにしたメモには左にバーを付けた

最初は文字の部分だけに色を付ける蛍光ペン風にし、次に行全体に色を敷く形を試しました。
行全体を塗ると、タスクが増えたときに画面の色が強くなりすぎ、チャットとしての読みやすさが落ちました。
そこで、メモの左に細い縦のバーを付ける形にしました。本文はほかのメモと同じように読めて、どれがタスクかもひと目で分かります。
タスクを完了すると、バーを同じ明るさの灰色に変え、本文を薄くします。チャットを見返すだけで、そのメモが「片づいたかどうか」まで分かります。

### ウィジェットでは1行だけに色を敷く

タスクが文字だけで並んでいると、読む気力がわかずに素通りしがちです。
そこで、1行だけに黄色を敷いておき、少なくともその1行は読んでもらえるようにしました。
チャットのタスクの色(オレンジ)とは意味が違うので、色も分けています。

色を敷く行は、ウィジェットを「見るたびに」変わるのが理想です。ですが、ウィジェットは見られた瞬間に処理を動かすことができません。端末のロックを解除したことを知る手段もありません。
そこで、15分ごとに色を敷く行を変えた表示を、先の6時間分まとめて作ってシステムに渡しています。
予定に入っている表示の切り替えは、ウィジェットの更新回数の上限に数えられません。
同じ行が続けて選ばれないようにする規則は `WidgetHighlight` にまとめ、毎回同じ乱数を使う単体テストで確かめています。

### アプリとウィジェットのデータ共有

ウィジェットはアプリとは別のプロセスで動くため、そのままではアプリのデータを読めません。
そこで SwiftData の保存ファイルを App Group の共有領域に置き、両方から同じファイルを読むようにしました。

- アプリはタスクを変えるたびに、すぐ保存してから `WidgetCenter` に更新を頼む。自動保存を待つと、ウィジェットが古い内容を読むことがあるため
- ウィジェットは読むだけで、データを読み直すのは、アプリから頼まれたときと、色を敷く行の予定を使い切ったときだけにしている。変化はアプリ側からしか起きないので、無駄な読み直しをしないため
- App Group が使えない署名で動かした場合、アプリはアプリ専用の領域に保存して動き続ける。ウィジェットは空の一覧ではなく「アプリのデータを読めません」と表示し、原因が分かるようにしている

### 画面の行の組み立てを画面から切り離した

「5分以上あいたら線」「日付が変わったら見出し」という並びの規則は、`ChatTimeline` という純粋な関数にまとめ、SwiftUI の画面から切り離しました。
画面を動かさなくても、境界の値(ちょうど5分、4分59秒、日付をまたぐ場合)を単体テストで確かめられます。
テストには Swift Testing を使っています。

### チャットは新しい500件だけを読み込む

メモを書き続けると件数は増え続けますが、開くたびに全部を読み込むと、開くまでの待ち時間が伸びていきます。
「思いついたらすぐ書ける」のがこのアプリの良さなので、開くのが遅くなると、書くこと自体が面倒になってしまいます。
そこで、開いたときは新しい500件だけを読み込み、いちばん上までスクロールしたときに、その前の500件を読み足すようにしました。
読み足したあとも、それまで見ていたメモが同じ位置に見えるようにしています。
データは消さずにすべて残します。読み込む範囲を絞るだけです。

開いたときにいちばん下(最新のメモ)を表示するのにも工夫が要りました。
`List` は行の高さを表示してから測るため、行を指定して下端へ送っても、測り終わるにつれて内容が伸び、最新の数件が画面の外に残ります。
そこで、下端までの距離を見ながら、2回続けて下端にいると確かめられるまで送り直しています。

### 入力欄に案内文を出さない

「何か書かなきゃ」と構えずに書き始められるよう、入力欄は空のままにしています。
書きかけの文字は `@AppStorage` に残すので、アプリを閉じても消えません。

### プロジェクトファイルを XcodeGen で生成する

`.xcodeproj` は差分が読みにくく、手で直すと壊れやすいファイルです。
そこで、ターゲットや App Group の設定を `project.yml` に書き、そこから生成するようにしました。
すぐ開けるように、生成した `.xcodeproj` もリポジトリに含めています。
署名に使うチーム ID は、公開リポジトリに含めないよう、git 管理外の `Local.xcconfig` に分けました。

## 無料の Apple アカウントで実機に入れるときの制約

- 署名の有効期限は7日。切れたら Xcode から入れ直す
- 同時に入れておけるアプリは3つまで
- アプリとウィジェット拡張で、App ID を2つ使う
- App Group は無料アカウントでも使えた(下の「確認の記録」を参照)

## 確認の記録

| 項目 | 結果 |
|---|---|
| シミュレーターで、App Group の領域に保存されるか | 確認済み(`Atamannaka.store` が App Group 側に作られる) |
| 無料アカウントの実機署名で、App Group を付けられるか | 確認済み(2026年11月、Xcode 27.0。アプリとウィジェットのプロビジョニングプロファイルに `group.com.yukarii.atamannaka` が入り、iPhone で起動できた) |
| 実機のウィジェットで、タスクを読めるか | 確認済み(iPhone のホーム画面のウィジェットに、アプリで作ったタスクが表示された) |
